## UI/UX authority stack

1. project/product/user evidence;
2. platform conventions;
3. W3C accessibility standards;
4. rendered/browser evidence;
5. reviewed design skills/patterns.

Useful ready-made skill sources:
- Anthropic `frontend-design`;
- `pbakaus/impeccable`;
- `hueyexe/frontend-agent-skills` (MIT);
- existing Emil/Apple/adapt/better-interface skills.

Community heuristics never outrank actual user evidence.

## SEO authority stack

1. Google Search Central/Search Console for Google Search;
2. current Bing/platform official docs where applicable;
3. project first-party analytics;
4. external crawlers/SEO providers;
5. community skill packs.

Reviewed:
`marketingskills/seo` — MIT — pattern/optional operational skill source.

Google explicitly warns that third-party tools do not have access to internal Google ranking data and cannot guarantee performance.

## Meta authority stack

1. current Meta Marketing API/Business SDK docs;
2. actual Ads Manager/API account evidence;
3. first-party event/measurement evidence;
4. Robyn/GeoLift where statistically appropriate;
5. observational attribution/ROAS.

Causal and observational measurement remain separate.

## Security testing authorization

DAST/fuzzing/security testing is performed only against:
- owned systems;
- explicitly authorized client systems;
- dedicated test targets.

Authorization must include:
- target;
- environment;
- test type;
- credentials/account scope when applicable;
- prohibited/destructive actions.

## Specialist evidence contract

A specialist recommendation should contain:
- authority/source;
- confidence;
- observation vs inference;
- exact affected surface;
- measurable acceptance criterion;
- verification method.

## Anti-duplication

JIT specialist aliases do not supersede stable domain owners.

Examples:
- `@SchemaEntityArchitect` routes through existing SEO owners.
- `@GraphicArtDirector` routes through existing brand/graphic roles.
- security aliases route through Security Reviewer.
- Meta remains existing stable agents.

## Completion

Specialist work is not complete merely because advice was produced. Material implementation needs:
- actual source/runtime change;
- domain verification;
- independent QA;
- recorded residual risk.
